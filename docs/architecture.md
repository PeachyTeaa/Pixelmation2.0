# Устройство проекта

## Слои

```
core  →  state  →  ui
  ↘        ↘
   tools    agent
```

**`src/core`** — чистые функции без React и без DOM. Здесь живут типы, разбор и
запись форматов, операции над сетками, растеризация и энкодеры PNG/GIF. Ядро
одинаково работает в браузере, в Node и в тестах; всё остальное — надстройки
над ним.

| Модуль | Ответственность |
| --- | --- |
| `types.ts` | типы и соглашение о координатах |
| `color.ts` | разбор и канонизация цветов, альфа, наложение |
| `grid.ts` | сетки: клетки, линии, фигуры, заливка, сдвиг, размер |
| `texture.ts` | операции над текстурой поверх `grid` |
| `animation.ts` | кадры, ссылки, санитайзер, `ensureColorRef` |
| `codec.ts` | `.pxlmt` и `.pxlma`, включая формат 1.x |
| `render.ts` | сетка цветов → RGBA-буфер |
| `ascii.ts` | текстовое и ANSI-превью |
| `png.ts` | PNG-энкодер (сжатие передаётся снаружи) |
| `gif.ts` | GIF89a-энкодер с собственным LZW |

**`src/state`** — zustand-хранилище. Документ хранится плоско: одна `texture`,
массив `slides` и имя; объект анимации собирается функцией `toAnimation`, чтобы
не было двух источников правды. Здесь же история отмен (снимки документа,
100 шагов), группировка мазка через `beginStroke`/`endStroke` и `persist` в
localStorage.

**`src/ui`** — React-компоненты. `PixelCanvas` умеет только рисовать сетку и
переводить события мыши в координаты клеток; логика инструментов вынесена в
хук `usePainter`, а он ходит в хранилище. Панели (`ToolsPanel`, `ColorPanel`,
`RefPanel`, `ExportPanel`, `SlidesTimeline`) собираются в `EditorScreen`.

**`src/agent`** — `window.pixelmation`: тот же набор действий, что у человека,
но вызываемый из консоли или из инструмента автоматизации.

**`tools/pxl.ts`** — командная строка поверх ядра, запускается через `tsx`.

## Соглашение о координатах

Сетка хранится построчно: `grid[y][x]`, где `y` — строка. Точка и ссылка на
пиксель — `{ x: столбец, y: строка }`. В формате 1.x оси у ссылок были
переставлены, поэтому импорт их меняет местами — это единственное место, где
живёт эта особенность (`codec.ts`).

## Почему canvas, а не div на пиксель

Первая версия рендерила каждый пиксель отдельным `<div>`, поэтому холст был
ограничен 75×75 и всё равно тормозил. Сейчас всё рисуется на одном `<canvas>`
с учётом `devicePixelRatio`, и 512×512 остаётся отзывчивым.

## Что не хранится в localStorage

История отмен, буфер копирования кадров и флаг проигрывания — состояние сессии.
Всё остальное (документ, инструмент, цвет, тема, фон, скорость) переживает
перезагрузку.

## Тесты

`npm run test:run` — vitest в jsdom. Ядро проверяется по существу: форматы
round-trip'ом, GIF — собственным LZW-декодером в тесте, PNG — распаковкой через
`zlib.inflateSync`. Хранилище и API агента проверяются как сценарии
пользователя: нарисовать, отменить, переставить кадры, сохранить.
