# Форматы файлов

Оба формата — обычный JSON в UTF-8. Расширение определяет тип, но парсер умеет
опознавать содержимое и по структуре.

Сетки пишутся упакованными в строку: пиксель-арт состоит из длинных повторов,
и RLE сжимает его в разы. Это единственный формат записи — и в редакторе, и в
CLI, и в API. Развёрнутые массивы остаются legacy: такие файлы открываются,
но сохраняются уже строкой (см. «Legacy: массивы» ниже).

## `.pxlmt` — текстура

```json
{ "name": "герой", "cells": "1=2.#ff0000ff,1.null;1=1.null,1.#00ff0080,1.null" }
```

- `name` — строка, имя текстуры;
- `cells` — упакованная сетка, индексируется как `cells[строка][столбец]`;
- цвет всегда пишется как `#rrggbbaa` в нижнем регистре;
- отсутствие цвета — всегда `null`. Полностью прозрачный цвет (`alpha = 0`)
  при сохранении превращается в `null`.

Правила упаковки:

- строки холста разделены `;`, каждая записана как `<повторов>=<строка>`;
- клетки внутри строки разделены `,`, каждая записана как `<повторов>.<цвет>`;
- кадры анимации разделены `+` и записаны как `<повторов>!<кадр>`.

Все строки холста обязаны быть одной длины — иначе файл считается битым и
редактор скажет, что именно не так.

При чтении дополнительно принимаются `#rgb`, `#rgba`, `#rrggbb`,
`rgb(...)`, `rgba(...)`, а также слова `"null"`, `"transparent"`, `"none"` —
всё это приводится к канону.

## `.pxlma` — анимация

```json
{
  "name": "бег",
  "slides": "1!1=1.null,1.0-0;1=1.0-1,1.null",
  "texture": { "name": "герой", "cells": "1=1.#ff0000ff,1.#00ff00ff" }
}
```

- `name` — имя анимации;
- `slides` — упакованные кадры; клетка кадра это `null` или ссылка на пиксель
  текстуры, записанная как `"строка-столбец"`;
- `texture` — вложенный документ формата `.pxlmt`.

Внутри программы ссылка живёт как точка `{ x: столбец, y: строка }` — в файле
оси стоят в обратном порядке, кодек переставляет их сам.

Размер каждого кадра совпадает с размером текстуры. При сохранении ссылки на
прозрачные или исчезнувшие пиксели заменяются на `null` — файл всегда
самосогласован.

### Почему ссылки, а не цвета

Кадр хранит адрес пикселя текстуры, а не сам цвет. Поменяли цвет в текстуре —
и он поменялся сразу во всех кадрах. Именно поэтому рисовать в анимации можно
только теми цветами, которые есть в текстуре.

## Legacy: массивы

Какое-то время `cells` и `slides` писались развёрнутыми массивами:

```json
{ "name": "герой", "cells": [["#ff0000ff", null], [null, "#00ff0080"]] }
```

```json
{ "name": "бег", "slides": [[[null, { "x": 0, "y": 0 }]]], "texture": { … } }
```

Такие файлы по-прежнему открываются: парсер смотрит на тип поля — строка это
или массив — и разбирает соответственно. Записывать в этом виде нельзя, при
сохранении документ уходит в строку. Отдельного ключа для экспорта в массивы
нет ни в редакторе, ни в `pxl`, ни в `window.pixelmation`; чтобы перегнать
старый файл, достаточно `pxl convert вход выход`.

## Ограничения

- сторона холста: от 1 до 512 (в первой версии было до 75);
- кадров в анимации: не ограничено, но каждый кадр хранится целиком;
- имена файлов чистятся от символов `\\ / : * ? " < > |`.
