# Форматы файлов

Оба формата — обычный JSON в UTF-8. Расширение определяет тип, но парсер умеет
опознавать содержимое и по структуре.

## `.pxlmt` — текстура

```json
{
  "name": "герой",
  "cells": [
    ["#ff0000ff", "#ff0000ff", null],
    [null, "#00ff0080", null]
  ]
}
```

- `name` — строка, имя текстуры;
- `cells` — двумерный массив **строк или `null`**, индексируется как
  `cells[строка][столбец]`;
- цвет всегда пишется как `#rrggbbaa` в нижнем регистре;
- отсутствие цвета — всегда `null`. Полностью прозрачный цвет (`alpha = 0`)
  при сохранении превращается в `null`.

Все строки массива обязаны быть одной длины — иначе файл считается битым и
редактор скажет, что именно не так.

При чтении дополнительно принимаются `#rgb`, `#rgba`, `#rrggbb`,
`rgb(...)`, `rgba(...)`, а также слова `"null"`, `"transparent"`, `"none"` —
всё это приводится к канону.

## `.pxlma` — анимация

```json
{
  "name": "бег",
  "slides": [
    [
      [null, { "x": 0, "y": 0 }],
      [{ "x": 1, "y": 0 }, null]
    ]
  ],
  "texture": { "name": "герой", "cells": [["#ff0000ff", "#00ff00ff"]] }
}
```

- `name` — имя анимации;
- `slides` — массив кадров; каждый кадр — двумерный массив клеток, где клетка
  это `null` или ссылка `{ "x": столбец, "y": строка }` на пиксель текстуры;
- `texture` — вложенный документ формата `.pxlmt`.

Размер каждого кадра совпадает с размером текстуры. При сохранении ссылки на
прозрачные или исчезнувшие пиксели заменяются на `null` — файл всегда
самосогласован.

### Почему ссылки, а не цвета

Кадр хранит адрес пикселя текстуры, а не сам цвет. Поменяли цвет в текстуре —
и он поменялся сразу во всех кадрах. Именно поэтому рисовать в анимации можно
только теми цветами, которые есть в текстуре.

## Совместимость с Pixelmation 1.x

В первой версии `cells` и `slides` сжимались в строки RLE:

```json
{ "name": "герой", "cells": "1=2.#ff0000ff;1=1.null,1.#00ff00ff" }
```

Правила чтения такой строки:

- строки холста разделены `;`, каждая записана как `<повторов>=<строка>`;
- клетки внутри строки разделены `,`, каждая записана как `<повторов>.<цвет>`;
- кадры анимации разделены `+` и записаны как `<повторов>!<кадр>`;
- ссылка на пиксель писалась как `"строка-столбец"` — **оси в обратном
  порядке** относительно нового формата.

Pixelmation 2.0 читает такие файлы сам: определяет по типу поля (строка против
массива) и переставляет оси ссылок. Обратная запись доступна флагом
«Формат Pixelmation 1.x» в панели экспорта, ключом `--legacy` в CLI и
параметром `{ legacy: true }` в API.

## Ограничения

- сторона холста: от 1 до 512 (в первой версии было до 75);
- кадров в анимации: не ограничено, но каждый кадр хранится целиком;
- имена файлов чистятся от символов `\\ / : * ? " < > |`.
